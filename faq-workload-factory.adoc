在设置和管理 NetApp Workload Factory 时，您可能会对有关帐户、凭据、链接和自动化工具的概念、术语、行为和限制有一些常见问题。



[[overview-and-costs]]
== 概述和费用

.什么是 Workload Factory，它的成本是多少？
Workload Factory 是一个生命周期管理平台，用于优化工作负载，例如数据库、VMware 迁移和 EDA 项目，这些工作负载在 FSx for ONTAP 文件系统上运行。Workload Factory 本身可免费使用。您需要为您部署的服务向 AWS 支付费用，例如 FSx for ONTAP 文件系统、VMware Cloud on AWS 基础架构和其他 AWS 服务。

link:workload-factory-overview.html["了解 Workload Factory"]。

.Workload Factory 在哪些 AWS 区域可用？
Workload Factory 适用于支持 FSx for ONTAP 的所有商业地区，但不适用于中国地区、Secret Cloud 或 Top Secret Cloud。

https://aws.amazon.com/about-aws/global-infrastructure/regional-product-services/["查看受支持的 AWS 区域。"^]



[[accounts-and-sign-in]]
== 帐户和登录

.Workload Factory 控制台和 NetApp Console 之间有什么区别？
两者都是基于 Web 的控制台，可让您访问 Workload Factory。NetApp 控制台提供混合体验，您可以在一个位置与其他数据服务一起管理 FSx for ONTAP 文件系统和工作负载。Workload Factory 控制台是一种专用体验，专注于在 FSx for ONTAP 上运行的工作负载。

link:console-experiences.html["决定使用哪个控制台"]。

.如何注册？创建首个账号后会发生什么？
使用您的 NetApp 支持站点（NSS）凭据注册，或者创建一个 NetApp 云登录。对于云登录，您必须先验证您的电子邮件地址，然后才能登录。首次登录时，您将创建一个帐户，用于组织您的资源、工作负载和凭据，并且您将成为拥有所有 Workload Factory 功能访问权限的帐户管理员。如果您已经使用 NetApp Console，则您已经属于某个帐户，因为 Workload Factory 使用 NetApp 帐户。

link:sign-up-and-log-in.html["注册并登录"]。

.我是否应该将我的账户设为 AWS GovCloud（美国）账户，以后可以更改吗？
如果您需要一个仅使用 GovCloud（美国）端点和区域，且凭据和机密保留在 GovCloud 中的帐户，请选择 GovCloud（美国）选项。此选择是永久性的。GovCloud 帐户必须手动添加凭据并创建链接。

.如何邀请其他用户加入我的 Workload Factory 帐户？
您只能从 NetApp Console 管理您的帐户。帐户管理员在其中添加成员，受邀用户会收到一封包含加入说明的电子邮件。

link:sign-up-and-log-in.html["邀请其他用户加入您的账号"]。



[[credentials-and-permissions]]
== 凭证和权限

.我必须添加 AWS 凭据才能使用 Workload Factory 吗？
开始使用时，添加凭据是可选的，因此您无需访问 AWS 帐户即可使用 Workload Factory。但是，要创建和管理 FSx for ONTAP 文件系统以及部署和管理数据库等工作负载，Workload Factory 需要凭据。

* link:quick-start.html["开始使用 Workload Factory"]。
* link:add-credentials.html["添加凭据"]。


.Workload Factory 凭据如何工作？
凭据使用 AWS 承担角色流。每组凭据由一个或多个 IAM 策略（基于您选择的工作负载功能和权限级别）以及 Workload Factory 承担的 IAM 角色组成。您可以稍后随时添加更多功能。

link:add-credentials.html["添加凭据"]。

.我应该手动添加凭据还是使用 CloudFormation？
使用手动方法，您可以在 AWS 管理控制台中创建 IAM 策略和 IAM 角色，并从 Codebox 复制策略 JSON。使用自动方法，您可以选择各项功能，然后由一个 CloudFormation 堆栈为您创建 IAM 策略和 IAM 角色。必须手动添加 GovCloud（美国）凭据，因为该区域不支持 CloudFormation。

link:add-credentials.html["添加凭据"]。

.我可以选择哪些权限级别，以及如何决定授予哪些权限？
权限策略按工作负载捆绑。对于存储，选项包括*查看、规划和分析*、*操作和修正*以及*文件系统创建和删除*。数据库工作负载提供*查看、规划和分析*、*操作和修正*以及*数据库主机创建*。这些策略允许您根据您的 IT 策略分配增量信任。仅选择您现在计划使用的功能。

link:permissions-reference.html["权限参考"]。

.自动权限检查的作用是什么，我应该保持启用状态吗？
选择 *启用自动权限检查* 会将 `iam:SimulatePrincipalPolicy`添加到您的权限策略中，以便 Workload Factory 可以在完成操作之前确认您拥有所需的 AWS 权限。您可以在添加凭据后将其删除，但建议将其保留。它可以防止为部分成功的操作创建资源，并使您免于手动清理资源。

link:add-credentials.html["添加凭据时启用自动权限检查"]。

.我可以删除不再需要的凭据吗？
仅当凭据未与 FSx for ONTAP 文件系统关联时，才能将其删除。在 Workload Factory 控制台中使用 *Remove*，或在 NetApp Console 中使用 *Delete*。

link:manage-credentials.html["删除凭据"]。



[[links]]
== 链接

.什么是 Link？我需要 Link 吗？
链接可在 Workload Factory 帐户与一个或多个 FSx for ONTAP 文件系统之间创建信任关系和连接。链接使用 AWS Lambda，因此您可以通过 ONTAP REST API 调用来监控和管理 Amazon FSx for ONTAP API 未提供的功能。您不需要链接即可开始，但您需要一个链接才能解锁所有 Workload Factory 功能。

link:links-overview.html["详细了解链接"]。

.哪些功能需要 Link？
需要链接的功能包括：

* FSx for ONTAP 的良好架构状态
* ONTAP EMS 事件监控
* 使用人工智能的自主勒索软件防护（ARP/AI）
* 卷和存储 VM 复制
* SMB/CIFS 共享和 NFS 导出策略
* iSCSI 卷管理
* Snapshot 策略
* 卷自动增长和 inode 管理
* 克隆创建
* 额外的 ONTAP 指标和 LIF 详细信息


如果您尝试执行需要链接但未关联任何链接的操作，Workload Factory 会提示您。请参阅 link:links-overview.html["详细了解链接"]。

.链接会增加费用吗？
是的。每个 Lambda 事务都会产生 AWS 费用。由于 Lambda 充当代理，因此当它向文件系统上的 ONTAP REST API 发送请求时，以及将响应发送回 Workload Factory 时，都会向您收费。

link:links-overview.html["详细了解链接"]。

.一个文件系统可以与多个 Link 关联吗？
一个链接可以与许多 FSx for ONTAP 文件系统相关联。每个文件系统只能与同一 NetApp 帐户中的一个链接相关联。如果您有多个 NetApp 帐户，一个文件系统可以与不同帐户下的其他链接相关联。请参阅 link:links-overview.html["详细了解链接"]。

.我应该自动还是手动创建链接？
自动创建会通过 Workload Factory 注册链接，但它使用令牌进行 Workload Factory 自动化，其 CloudFormation 代码最多只能使用六个小时。手动创建使用 Codebox 中的 CloudFormation 或 Terraform，并且代码会持久保留。当安全和 DevOps 等团队必须首先授予权限时，这非常有用。GovCloud 帐户必须手动创建链接。

link:create-link.html["创建链接"]。

.在创建链接之前，我需要准备什么？
您需要在文件系统的安全组中打开所需的端口，Link 能够访问 `\https://api.workloads.netapp.com`，以及拥有足够的 AWS 权限来创建 CloudFormation 堆栈。

link:create-link.html["了解创建链接的完整先决条件列表"]。

.我可以更改链接的身份验证方式，或在创建链接后编辑链接吗？
不可以。链接仅支持一种身份验证方法，即 Workload Factory 凭据或 AWS Secrets Manager，您以后无法对其进行更改。

您无法在界面中编辑链接。若要进行更改，请创建一个新链接并将其与文件系统关联。不建议在 AWS 中更改 Lambda 网络配置，因为这可能会导致连接问题。

link:manage-links.html["管理链接"]。

.删除链接后会发生什么？
使用该 Link 的文件系统和其他资源将无法再使用依赖于它的功能。该 Link 仅从 Workload Factory 中删除，而不会从 AWS 中删除，因此您还必须删除 AWS 帐户中的 Lambda 函数。

link:manage-links.html["删除链接"]。



[[codebox]]
== Codebox

.什么是 Codebox，它会生成哪些代码格式？
Codebox 是一个基础架构即代码辅助工具，可生成代码以运行 Workload Factory 支持的任何操作。它支持 Workload Factory REST API、AWS CLI、AWS CloudFormation 和 Terraform。Codebox Viewer 显示从向导条目生成的代码，Automation Catalog 将保存的作业存储为可重用的模板。

link:codebox-automation.html["了解有关CodeBox的更多信息"]。

.我可以在 Codebox 中编辑代码吗？生成的代码会过期吗？
Codebox Viewer 是只读的。您只能复制代码，将其保存到自动化目录，或下载某些格式的代码。您可以编辑下载的代码，使其适应其他 AWS 帐户。出于安全原因，CloudFormation YAML 代码在七天后过期。

link:use-codebox.html["使用 Codebox"]。



[[cloudshell]]
== CloudShell

.我在 CloudShell 中可以做什么，它有哪些局限性？
CloudShell 使用您提供的 AWS 和 ONTAP 凭据，在基于浏览器的 shell 中运行 AWS CLI 和 ONTAP CLI 命令，并通过 Workload Factory 后端进行代理。它至少需要一个 AWS 凭据。不支持管道 `|`、后台 `&`和重定向 `>`等 Shell 运算符，包含这些运算符的命令将会失败。仅当所选凭据在所选区域中具有权限时，AWS 命令才会成功。

link:use-cloudshell.html["使用CloudShell"]。



[[notifications]]
== 通知

.Workload Factory 可以在哪里发送通知，由谁控制？
Workload Factory 可以将通知作为 NetApp Console 警报发送，也可以作为电子邮件发送到与帐户关联的地址，或者发送到 Amazon SNS 主题。当您部署了 Console 代理或 Link 时，会出现 Console 警报。当您在 NetApp Console 中配置通知时，它将接管发送的所有权，并且 Workload Factory 控制台通知选项将变为只读。

link:configure-notifications.html["配置通知"]。

.在使用 Amazon SNS 发送关键警报之前，我应该知道些什么？
Workload Factory 仅支持标准 SNS 主题类型，这并不能保证通知按接收顺序到达订阅者。对于关键或紧急通知，请考虑这一点。默认情况下，订阅者会接收有关主题的所有通知，因此请使用 SNS 筛选策略（按资源类型、工作负载、优先级或通知类型）仅接收您需要的内容。

link:configure-notifications.html["配置通知"]。



[[service-accounts]]
== 服务帐户

.我应该在何时使用服务帐户，关于其密钥我应该了解些什么？
将服务帐户用于仅 API 的自动化，以便脚本不依赖于个人的用户帐户。客户端密钥仅显示一次，并且 Workload Factory 不会存储它，因此请在创建服务帐户时复制或下载它。从客户端 ID 和密钥生成的访问令牌具有时效性，仅持续几个小时。在 Workload Factory 控制台中，您只能创建或删除服务帐户。要获取新密钥，请删除该服务帐户并创建一个新帐户。

link:manage-service-accounts.html["管理服务帐户"]。



[[well-architected-analysis]]
== 精心设计的分析

.架构完善的分析是如何工作的，是否需要 Link？
Workload Factory 每天扫描 FSx for ONTAP 文件系统。它将配置评为优化或未优化，提供建议，并可以自动修复某些问题，而其他问题则需要手动步骤。您可以忽略不适用于您的环境的检查，或以简单语言创建自定义规则。要对文件系统进行全面分析，您需要创建一个 Link 并将其与之关联。

link:well-architected-workloads.html["详细了解精心设计的分析"]。



[[tracker]]
== 跟踪器

.什么是 Tracker，它会保留作业历史记录多长时间，以及我可以对失败的作业做些什么？
Tracker 是 Workload Factory 中的监控工具，在用户界面中保留事件 30 天。您可以按时间范围、工作负载、状态和用户进行筛选，并以 CSV 文件的形式下载作业表。对于失败的操作，您可以重试，或者编辑其参数并重试。失败操作允许的重试次数是有限的。

link:monitor-operations.html["使用 Tracker 监控操作"]。



[[ai-features]]
== AI 功能

.如何控制 AI 功能，如果关闭它们会发生什么？
在 AI 设置页面上，管理员可以选择 NetApp 托管的 Bedrock（推荐）或关闭所有 AI 功能。NetApp 托管的 Bedrock 不会使用您的数据来训练模型，也不需要额外的 AWS 设置。关闭 AI 功能会使 Ask Me、AI 代理、自定义仪表板、规则生成器、分析器以及 CloudShell 中的 AI 错误响应不可用。AI 功能在公共 AWS 区域中使用 AWS Bedrock，这对 GovCloud 帐户可能很重要。

link:manage-genai-features.html["管理 AI 功能"]。

.人工智能的使用是否有限制？
是的。对于受 NetApp 管理的 Bedrock，每个帐户对每个 AI 功能都有每月支出限制。当达到限制时，Workload Factory 会关闭 AI 功能，灰显界面的相关部分，并显示工具提示。要获得更多消费金，请联系您的 NetApp 代表。

.AI 代理可以更改我的 AWS 或 ONTAP 资源吗？
默认情况下，代理以只读模式运行，无法更改资源。在可选的读/写模式下，代理会总结每个操作，并仅在您批准后使用您选择的凭据执行该操作。代理只能访问您当前范围内的资源以及在代理设置中选择的凭据，并且选择凭据不会授予额外的 AWS 权限。

* link:learn-agent.html["了解 AI 代理"]。
* link:manage-agent-settings.html["管理代理设置"]。




[[custom-dashboards]]
== 自定义信息板

.谁可以查看、编辑或删除自定义仪表板？
新控制面板仅供创建者使用。共享会使控制面板对您的 Workload Factory 帐户中的所有人公开，并且您无法在帐户外部进行共享。只有创建者可以编辑控制面板，但帐户中的所有用户都可以将其删除。删除操作是永久性的，并且会为所有人删除该控制面板，因此请与您的团队进行协调。

* link:learn-custom-dashboards.html["了解自定义控制面板"]。
* link:manage-custom-dashboards.html["管理自定义仪表板"]。


.要创建和使用自定义控制面板，我需要做些什么？
您的账号管理员应启用 AI 功能。您需要具有要监视的服务的读取访问权限的 AWS 凭据。您需要一个 Link 来连接到 FSx for ONTAP 文件系统。仪表板是只读的，无法更改您的存储或工作负载设置。

link:learn-custom-dashboards.html["了解自定义控制面板"]。
